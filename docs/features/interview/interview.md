# AI 인터뷰 - interview.md

## 요구사항 인터뷰

### 목적

초기 기능 정의서의 모호성을 제거하고, 엣지 케이스와 결정 사항을 확정한다.

### 입력

- `docs/features/planner/planner.md`  기능의 인터뷰 내용을 해당 경로의 내용을 참고하여 진행
- CSS 관련 내용은 css-standards.skill 을 참조한다.

### 핵심 활동

**AI를 인터뷰어로 활용한다.** 프롬프트 패턴:

```
이 정의서를 바탕으로, 
코드베이스를 탐색하고 구현 전에 확인이 필요한 것들을
나에게 질문해라. 
한 번에 하나씩 질문하고, 
추천 방식도 이유와 함께 포함하라.
```

**질문 템플릿** (AI가 다뤄야 할 영역): 유지보수성 까지 다뤄야 한다.

1. 이 기능의 primary user(등록자, 신청자)는 누구인가?
2. 최소 동작 시나리오 3개는? (가장 기본적인 사용 흐름)
3. 데이터 저장 방식 — 기존 구조와의 관계는?
4. 경계 조건 — 최대값, 빈 값, 중복, 동시성은?
5. 에러 처리 — 실패 시 사용자에게 어떻게 표시하는가?
6. 기존 UI 패턴과의 일관성 — 어떤 컴포넌트를 재사용할 수 있는가?
7. 성능 제약 — 허용 응답 시간, 데이터 크기 제한은?, 데이터 소멸 경계
8. 향후 확장 가능성 — 이 결정이 다음 기능 특징에 영향을 주는가?
9. CSS 조작은 css-standards.skill 을 참조하여 CSS를 만들지만 예외 사항을 둬야하는 기능은 질문을 한다.

**Ubiquitous Language 정의:**

- 인터뷰 과정에서 사용되는 용어를 고정한다
- 코드·문서·대화에서 같은 단어로 같은 것을 가리킨다
- spec-fixed.md에 "용어 정의" 섹션으로 명시한다
