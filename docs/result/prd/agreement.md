## 1. 개요

### 목적
가입자가 화면에서 직접 서명하고, 그 서명이 병합된 PDF 동의서를 위조 불가능한 형태로 보관한다.

### 왜 별도 도메인인가
가입 플로우의 한 단계처럼 보이지만, 다루는 것이 **파일·해시·법적 증거**로 회원 도메인과 성격이 완전히 다르다. 저장소·보관 정책·CSS 예외까지 따로 걸린다.

### 범위
- 서명 캔버스 (터치·마우스)
- `pdf-lib`로 서명 PNG를 템플릿 PDF에 병합
- 병합 PDF 저장 + SHA-256 해시 기록
- 동의서 조회 / 관리자 열람
- 동의서 템플릿 버전 관리

### 핵심 제약
**원본 서명 PNG는 병합 직후 폐기한다.** 남겨두면 재사용·위조 위험이 생긴다. (spec-fixed §2.3)

---

## 2. 사용자 스토리

- **가입자로서** 마우스나 손가락으로 직접 서명하고, 마음에 안 들면 지우고 다시 그리고 싶다.
- **가입자로서** 서명한 동의서가 실제로 어떻게 생겼는지 확인한 뒤 제출하고 싶다. 무엇에 동의하는지 모르고 누르고 싶지 않다.
- **가입자로서** 나중에 내가 동의한 문서를 다시 볼 수 있기를 원한다.
- **운영자로서** 분쟁이 생겼을 때 "이 사람이 이 시각에 이 내용에 동의했다"를 증명할 수 있어야 한다.
- **운영자로서** 동의서 문구를 개정해도 기존 동의서가 그대로 보존되기를 원한다. 과거 동의를 새 문구로 소급하면 증거 능력이 사라진다.

## 4. Out of Scope

| 항목 | 이유 |
|---|---|
| 공인전자서명 / 인증서 기반 서명 | 법적 효력 등급이 올라가지만 인증기관 계약 필요. MVP 범위 밖 |
| 타임스탬프 기관(TSA) 연동 | 위와 동일 |
| 서명 원본 PNG 보관 | **의도적으로 폐기** (재사용·위조 위험). 병합 PDF + 해시만 남긴다 |
| 동의서 내용의 사용자별 커스터마이징 | 템플릿은 전원 동일 |
| PDF 내 텍스트 입력·체크박스 폼 | 서명 한 곳만 |
| 동의서 이메일 자동 발송 | 사이트에서 조회만 |
| 다중 서명 (양자 서명) | 가입 동의서는 단독 서명 |
| 서명 이미지 벡터화 / 필적 검증 | 과함 |
| PDF 전자서명(디지털 서명) 필드 삽입 | 해시 기록으로 무결성 확인을 대체 |

## 5. 용어 정의

| 용어 | 코드 식별자 | 정의 |
|---|---|---|
| 동의서 | `Agreement` | 서명이 병합된 PDF 및 그 메타데이터 |
| 템플릿 버전 | `templateVersion` | 동의서 문구 개정 차수 |
| 무결성 해시 | `sha256` | 병합 PDF의 SHA-256. 위조 여부 판정 근거 |

## 6. CSS 예외 (확정)

`css-standards` 규약에서 **예외를 허용하는 두 화면 중 두 곳이 모두 이 도메인**이다. (spec-fixed §10)

| 화면 | 예외 | 이유 |
|---|---|---|
| 서명 캔버스 | 고정 px 캔버스 + `devicePixelRatio` 스케일링 | rem/%로는 터치 좌표가 어긋나 PDF에 서명이 틀어진 위치로 박힌다 |
| PDF 뷰어 | 원본 종횡비 고정 컨테이너 | 문서 비율 왜곡 방지 |
