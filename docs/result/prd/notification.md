## 1. 개요

### 목적

사용자가 사이트에 들어와 있지 않은 순간에 벌어지는 일(조건 변경, 수락, 모집 미달, 제재, 환전 승인)을 놓치지 않게 한다.

### 왜 별도 도메인인가

알림은 **모든 도메인이 호출하는 공통 기반**이고, 스케줄러는 **어느 도메인에도 속하지 않는 시간 축**이다. 각 도메인에 흩어두면 발송 방식과 중복 방어가 제각각이 된다.

### 범위

- 인앱 알림 (`Notification` 테이블 + 헤더 벨)
- 이메일 발송 (Resend, `MailProvider` 추상화)
- 스케줄 작업 4종
- 멱등성 + PostgreSQL advisory lock

### 이 도메인의 실패 모드

**중복 발송**과 **미발송**이다. 둘 다 사용자 신뢰를 깎는데, 원인이 코드가 아니라 운영 환경(서버 대수)에 있어 로컬에서 재현이 안 된다.

## 2. 사용자 스토리

### 받는 쪽

- **구직자로서** 내가 신청한 공고의 조건이 바뀌면 즉시 알고 싶다. 사이트에 다시 들어와야만 알 수 있으면 늦는다.
- **구직자로서** 수락·거절 결과를 바로 알고 싶다. 다른 일자리를 찾을지 판단해야 한다.
- **구인자로서** 시작 3시간 전에 인원이 안 찼으면 알림을 받고 연장·삭제·유지를 고르고 싶다.
- **회원으로서** 같은 알림이 두 번 오지 않기를 원한다. 두 번 오면 시스템을 못 믿게 된다.
- **회원으로서** 중요한 건(제재·환전)은 이메일로도 받고 싶다. 사이트에 안 들어와도 알아야 한다.
- **회원으로서** 인증 코드 메일이 스팸함으로 가지 않기를 원한다.

### 운영하는 쪽

- **운영자로서** 서버를 두 대로 늘려도 알림이 두 번 가지 않기를 원한다.
- **운영자로서** 알림이 실제로 나갔는지 DB에서 확인할 수 있어야 한다. "안 왔다"는 문의에 답해야 한다.

## 4. Out of Scope

| 항목                                   | 이유                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| SMS / 카카오 알림톡                    | 유료 + 발신프로필·템플릿 심사 (spec-fixed 라운드 4 결정) |
| 웹푸시 / PWA 푸시                      | MVP 웹 전용 확정. iOS 제약도 있음                        |
| 실시간 알림 (WebSocket / SSE)          | 폴링 또는 페이지 로드 시 조회로 갈음                     |
| 알림 설정 화면 (수신 거부 / 채널 선택) | 전원 동일 정책                                           |
| 알림 그룹핑 / 요약 다이제스트          | 건별 발송                                                |
| 마케팅 메일 / 뉴스레터                 | 트랜잭션 메일만                                          |
| 알림 읽음 동기화 (다중 기기)           | 단순 플래그                                              |
| BullMQ / Redis 기반 지연 잡            | advisory lock + Cron으로 갈음. 스케일아웃 시 재검토      |
| 이메일 열람 추적 (오픈율·클릭률)       | 없음                                                     |
| 다국어 알림                            | 국내 서비스                                              |

## 5. 용어 정의

| 용어        | 코드 식별자     | 정의                                 |
| ----------- | --------------- | ------------------------------------ |
| 알림        | `Notification`  | 인앱 알림 1건                        |
| 발송 채널   | _(개념)_        | 인앱 / 이메일 2종                    |
| 멱등 플래그 | `notifiedAt` 등 | 잡 대상 행에 두는 "이미 처리함" 표시 |

### 확정 사항

**이메일 병행 대상 (6종)**
재동의 요청 / 수락·거절 / 모집 미달 / 제재 발생 / 계좌 검증 완료 / 환전 승인·완료·반려

**스케줄 작업 (4종, 1분 주기)**

| 작업           | 조건                                        | 담당 |
| -------------- | ------------------------------------------- | ---- |
| 모집 미달 알림 | `OPEN` && 시작 3시간 전 && 확정 인원 < 정원 | B    |
| 공고 자동 마감 | 시작 시각 도달                              | B    |
| 환전 가능 전환 | `PAYOUT` 후 7일 경과                        | A    |
| 개인정보 파기  | 비활성화 후 4개월 경과 (일 1회)             | A    |

> **제재 해제는 잡이 아니다.** `Suspension.endAt` 경과를 조회 시점에 판정한다.

**중복 실행 방어 (2중)**

1. 멱등성 — 대상 행의 `notifiedAt IS NULL` 조건절
2. 분산락 — `pg_try_advisory_lock(jobKey)`. Redis 불필요
