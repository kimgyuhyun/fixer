## 3. 넘겨받는 사람이 알아야 할 것

### 3-1. 포트만 채우면 되는 자리 — #17이 열쇠다

`Application` 모델이 없어서 **세 곳이 0을 돌려주는 임시 구현체**로 배선돼 있다.
로직과 테스트는 다 있고, 어댑터만 채우면 그대로 동작한다.

| 어디                                     | 지금         | #17에서 할 일               |
| ---------------------------------------- | ------------ | --------------------------- |
| `auth.module.ts`의 `WithdrawalGuard`     | 항상 `false` | 진행 중 계약·본인 공고 판정 |
| `job-post.module.ts`의 `AcceptedCounter` | 항상 `0`     | 수락된 신청 수 세기         |

이 때문에 **AC 두 개가 지금 실제로는 동작하지 않는다.**

- **#9 AC4·AC5** — 진행 중 계약이나 열린 공고가 있어도 탈퇴가 안 막힌다
- **#16 AC2** — 수락자가 있어도 `Penalty`가 안 쌓인다

> **임시 구현체는 조용히 통과한다.** 지우는 것을 잊어도 빨개지는 테스트가 없다.
> 그래서 #16에는 `should always report penalized false while the accepted
counter is stubbed`라는 테스트를 뒀다 — 어댑터를 채우면 그게 빨개지면서
> "이제 AC2를 켜라"고 알려준다.

### 3-2. 실결제·알림이 있어야 닫히는 AC

| 이슈 | 무엇이 절반인가              | 언제 닫나             |
| ---- | ---------------------------- | --------------------- |
| #28  | 포트원 **결제창이 안 뜬다**  | 채널키가 생기면 한 줄 |
| #30  | 검증 완료 **알림이 안 간다** | 알림 도메인이 생기면  |

둘 다 서버 쪽 검증(금액 대조·멱등·서명·암호화)은 지금 전부 동작한다.

### 3-3. 파기 대상은 컬럼이 늘 때마다 늘려야 한다

`#39 파기 배치`는 지금 이름·이메일·주소·인증 이력·동의서 PDF를 지운다.
**연락처(`phone`)와 계좌는 빠져 있다** — 전자는 컬럼이 없고, 후자는 #30에서
방금 생겼다.

**#30이 만든 `ExchangeAccount`를 파기 대상에 더해야 한다.** 안 더하면 탈퇴
4개월 뒤에도 암호화된 계좌가 남는다. 이건 A가 남긴 숙제다.

## 4. 형님이 정해 놓은 것 중 김규현이 다시 열 수 있는 것

`point-money`는 PRD가 **두 사람이 함께 결정한다**고 정해 둔 도메인인데,
A가 혼자 정한 것이 둘이다. 이견이 있으면 다시 연다.

| ADR         | 결정                                  | 되돌리기 난이도                    |
| ----------- | ------------------------------------- | ---------------------------------- |
| `ADR-PAY-7` | 환불은 오래된 결제 건부터 소진 (FIFO) | **높음** — 충전 구조 자체가 얽힌다 |
| `ADR-PAY-6` | 계좌 암호화는 환경변수 마스터 키      | 낮음 — 포트 뒤라 KMS로 갈아끼운다  |

`ADR-PAY-7`의 기각안 중 "충전을 없애고 공고 등록 시 그 금액만 결제"가
**되돌리기 가장 어려운 기각**이다. PRD에 그렇게 적어 뒀으니 거기부터 보면 된다.
