# 작업 순서와 A/B 분담

> 선행 관계(위상 정렬) + 도메인을 끝까지 끝내는 순서로 정렬했다.
> **위에서부터 그대로 내려가면 선행 이슈가 막힌 적이 없다.**
> A가 앞 19개를 끝까지 만들고, 그 다음 B가 뒤 18개를 이어서 만든다.

## 나누는 규칙

**이슈 목록을 반으로 자른다.** 이슈 하나 안에서 역할을 나누지 않는다.

```
A  #3 → #4 → #5 → ... → #16    (19개)  한 사람이 순서대로 끝까지
                ↓  A가 다 끝나면 통째로 넘긴다
B  #17 → #18 → ... → #33       (18개)  받아서 순서대로 끝까지
```

이슈 하나는 **한 사람이 처음부터 끝까지** 만든다 — 시나리오, Red, Green, AC 검증, 리팩토링, 보안, PR까지. 중간에 사람을 바꾸지 않는다.

그 다음부터는 각자 자기가 만든 기능을 맡아 유지보수한다. A는 회원·동의서·포인트·공고를, B는 지원·제재·알림·관리자를 안다.

## 이 순서가 이렇게 나온 이유

**선행 관계는 절대 조건이다.** `#12 공고 등록`은 `#11`과 `#28`을 필요로 하므로 그 뒤에 온다. 순서를 어기면 선행 이슈의 결과물이 없어 작업이 막힌다.

**그 안에서는 도메인을 끝까지 끝낸다.** 회원 인증을 하다 말고 포인트로 넘어가면 맥락을 두 번 세운다. `#3~#6`으로 로그인 흐름을 완성하고, `#7~#8`로 동의서를 닫고, 그 다음 포인트로 간다.

**관리자 화면은 그 도메인이 다 끝난 뒤에 온다.** 관리할 대상이 없는데 관리 화면부터 만들 수 없다.

**#27 포인트 원장 코어가 7번인 이유:** 이것 하나가 `#28`·`#23`을 열어 가장 많은 하위 작업을 풀지만, 화면이 없는 코어 모듈이라 먼저 해봐야 눈에 보이는 게 없다. 회원·동의서를 눈에 보이게 끝낸 뒤에 넣었다.
