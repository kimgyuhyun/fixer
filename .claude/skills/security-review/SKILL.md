# 커밋 전 점검 — 타입과 보안

```
리팩토링 완료 🟢  (tdd-refactor 산출물)
    ↓ /security-review {N}
수집 → 3분류 → [GATE] 승인 → 즉시 수정만 처리 → 재스캔
    ↓
commit → PR
```

**사용법:** `/security-review 12` (GitHub 이슈 번호)

> **이름 참고:** Claude Code에 같은 이름의 내장 명령이 있다. 저장소의 이 스킬이 우선하며, 여기서 정의한 절차를 따른다.

---

## 이 단계의 목적은 "고치는 것"이 아니라 "분류하는 것"

스캐너는 판단하지 않는다. 취약점 20개를 뱉어도 그중 대부분은 개발 의존성이거나 이 프로젝트와 무관한 경로다. **전부 고치려 들면 무관한 의존성을 올렸다가 빌드가 깨진다.**

그래서 이 스킬의 산출물은 **판단이 붙은 목록**이다. 무엇이 진짜 위험이고 무엇이 소음인지 구분해서 개발자에게 넘긴다.

---

## 실행 순서

### 1. 타입 오류를 수집한다

```bash
pnpm typecheck
```

> **빌드가 타입 검사보다 먼저다.** Next 16이 `LayoutProps` 같은 전역 타입을 `next build` 때 생성하므로, 빌드 전에 `tsc`를 돌리면 `apps/web`에서 실패한다. 실패하면 `pnpm build`를 먼저 돌리고 다시 시도한다.

### 2. 의존성 취약점을 수집한다

**먼저 예외 대장을 읽는다.**

```bash
cat docs/result/security-exceptions.md
```

여기 이미 판정된 항목은 다시 조사하지 않는다. 근거를 대고 ⚪로 넘기되, **재검토 날짜가 지났으면 다시 판단한다.**

```bash
pnpm audit
```

각 항목에서 볼 것:

- **심각도** (critical / high / moderate / low)
- **도달 경로** — 서버가 실제로 실행하는 코드인가, 빌드·CLI 전용인가
- 대장에 이미 있는가

**심각도 하나로 정하지 않는다.** 빌드 도구의 high보다 요청 경로의 moderate가 더 급하다. 판정 기준은 대장의 표를 따른다.

| 도달 경로      | 심각도          | 처리                      |
| -------------- | --------------- | ------------------------- |
| 운영 코드 경로 | critical · high | 🔴 즉시 수정              |
| 운영 코드 경로 | moderate 이하   | 🟡 권장                   |
| 빌드·CLI 전용  | 전부            | ⚪ 대장에 기록하고 넘어감 |

**`pnpm audit --prod`를 믿지 않는다.** peerDependency를 운영 트리로 세기 때문에, 실제로는 CLI 전용인 것이 운영 경로로 잡힌다. 도달 경로는 직접 확인한다.

```bash
pnpm why <패키지명> -r
```

의존 사슬을 보고 **그 패키지를 부르는 쪽이 런타임인지 CLI인지** 판단한다. 판단 근거는 보고서에 남긴다 — 다음 사람이 같은 추적을 반복하지 않게.

### 3. 비밀값 노출을 확인한다

**`.env` 값이 코드에 직접 박혀 있는지 본다.**

```bash
grep -rnE "(SECRET|TOKEN|PASSWORD|API_KEY|CLIENT_ID|REFRESH_TOKEN)\s*[:=]\s*['\"][^'\"]{8,}" \
  apps/*/src packages/*/src 2>/dev/null | grep -v '/generated/'
```

알려진 접두사도 훑는다.

```bash
grep -rnE "(GOCSPX-|sk_live_|sk_test_|AKIA[0-9A-Z]{16}|ghp_|gho_)" \
  apps/*/src packages/*/src docs 2>/dev/null
```

**`.env` 자체가 커밋 대상에 올라와 있는지도 본다.**

```bash
git status --porcelain | grep -E '^\?\?|^A |^M ' | grep -E '\.env$|\.env\.'
```

`.env.example`은 올라가도 되지만 **값이 아니라 키 이름만** 있어야 한다.

### 4. 이 프로젝트에서 특히 볼 것

| 항목                             | 확인 방법                                                       | 왜                                                                                               |
| -------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **`NEXT_PUBLIC_` 접두사**        | 시크릿에 이 접두사가 붙었는지                                   | 이 접두사가 붙으면 **브라우저 번들에 그대로 들어간다.** 서버 전용 값에 붙이면 전 세계에 공개된다 |
| **인증 코드·비밀번호 평문 저장** | `codeHash`·bcrypt를 거치는지                                    | DB가 유출되면 그대로 쓸 수 있는 값이 남는다                                                      |
| **개인정보 로깅**                | `console.log`/`logger`에 이메일·계좌·인증코드·토큰이 들어가는지 | 로그는 오래 남고 접근 통제가 약하다                                                              |
| **에러 응답의 내부 정보**        | 5xx 응답에 스택·접속 문자열이 섞이는지                          | 공격자에게 구조를 알려준다                                                                       |
| **쿠키 옵션**                    | `httpOnly` / `secure` / `sameSite`                              | `spec-fixed.md` §2.5에서 확정된 사항                                                             |
| **입력 검증 누락**               | 컨트롤러가 zod로 `parse`하는지                                  | 검증 없이 DB로 가는 경로가 있으면 안 된다                                                        |

```bash
grep -rnE "console\.(log|info|debug)" apps/*/src packages/*/src | grep -v '/generated/'
```

### 5. 세 가지로 분류해 보고한다

| 분류                  | 기준                                  | 예                                                                                       |
| --------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| 🔴 **즉시 수정 필요** | 보안 위험 또는 빌드 실패 수준         | 비밀값이 코드에 있음, 시크릿에 `NEXT_PUBLIC_`, 운영 의존성의 critical/high, 타입 오류    |
| 🟡 **권장 수정**      | 코드 품질 저하. 지금 안 고쳐도 동작함 | 개인정보가 로그에 찍힘, `any` 사용, 운영 의존성의 moderate                               |
| ⚪ **무시 가능**      | 오탐이거나 의도된 패턴                | 빌드·CLI 전용 취약점, 테스트용 더미 값, 주석 안의 예시 문자열, **대장에 이미 있는 항목** |

각 항목에 담을 것: **파일·줄**, **무엇이 문제인지**, **왜 그 분류인지**, **어떻게 고치는지**.

**"무시 가능"에도 이유를 쓴다.** 근거 없이 넘긴 것과 판단해서 넘긴 것은 다르다. 다음 사람이 같은 항목을 다시 조사하지 않게 하는 게 목적이다.

**반복해서 나올 ⚪는 대장에 기록한다.** `docs/result/security-exceptions.md`에 의존 경로·수용 이유·재검토 날짜·해소 조건을 적는다. 일회성 오탐은 적지 않는다 — 대장이 길어지면 아무도 안 읽는다.

**예외가 3건을 넘으면 보고한다.** 관리되고 있지 않다는 신호다.

### 6. 승인 후 "즉시 수정 필요"만 처리한다

```
[GATE] 개발자 승인 전에는 아무것도 고치지 않는다
```

- 🔴만 고친다. 🟡은 보고만 하고 다음 이슈나 별도 작업으로 넘긴다
- 고친 뒤 **`pnpm test`로 회귀를 확인한다**
- 판단이 필요한 항목(의존성 올리기, 라이브러리 교체)은 반드시 승인을 받는다

### 7. 재스캔해서 클린 상태를 확인한다

```bash
pnpm typecheck && pnpm audit && pnpm test
```

남은 항목이 있으면 **그것이 🟡·⚪로 의도적으로 남긴 것인지** 명시한다.

## 비밀값이 이미 노출됐다면

**코드에서 지우는 것으로 끝나지 않는다.** 이미 대화·커밋·로그에 남았다면 그 값은 살아 있는 것으로 봐야 한다.

1. **해당 자격증명을 즉시 폐기·재발급한다** (발급처에서)
2. 그 다음에 코드·`.env`를 정리한다
3. 커밋 이력에 들어갔다면 이력에서 지우는 것까지 필요하다 — 이건 되돌리기 어려우므로 사람이 판단한다

순서가 중요하다. **코드만 지우고 키를 살려두면 아무것도 막지 못한다.**

---

## 제약

- **판단이 필요한 항목은 반드시 승인 후 수정한다.** 스캐너 결과를 그대로 실행하지 않는다
- **테스트 파일 수정 금지**
- **`pnpm audit --fix` 계열을 쓰지 않는다.** 메이저 버전을 임의로 올려 빌드를 깨뜨린다. 의존성 변경은 사람이 판단한다
- 발견한 비밀값을 **보고서에 그대로 옮겨 적지 않는다.** 파일·줄과 변수명까지만 쓴다
- 🟡·⚪ 항목을 임의로 고치지 않는다

---

## 흔한 실수

- **취약점 개수만 보고하기.** 20개 중 18개가 devDependencies면 실제 위험은 2개다. 분류가 이 스킬의 산출물이다
- **`audit fix --force` 실행.** 빌드가 깨지고 원인을 찾는 데 더 오래 걸린다
- **`.env.example`에 진짜 값 넣기.** 키 이름만 둔다
- **보고서에 시크릿 전문 복사.** 보고서 자체가 유출 경로가 된다
- **코드만 지우고 키는 그대로 두기.** 이미 노출된 값은 폐기가 먼저다
- **🟡까지 다 고치기.** 이슈 범위를 넘고 리뷰가 커진다
